# Microsoft 365 — connecting the Graph (Outlook + Excel + calendar) guard

Microsoft 365 is reached entirely through Microsoft Graph
(`https://graph.microsoft.com`). One `connector add m365` → **one** wire
guard-system (`graph`), public egress. All of Office (Outlook mail, Excel, calendar,
and later OneDrive/SharePoint, Teams) lives behind that one host with clean paths,
so it is **one** guard whose rules discriminate by path.

## The model: the AI acts as a connected account (delegated OAuth) — gmail-shaped

Like Gmail, the M365 employee acts as a **connected account** via delegated
authorization-code OAuth: a human signs in once in the browser and consents, the
platform stores the account's refresh-token bundle, and the guard refreshes a Graph
access token per request and injects `Authorization: Bearer …`. The employee never
sees a credential.

Because the token is delegated, every Graph call addresses `/v1.0/me/…`, which
resolves to the signed-in account — the agent never passes a mailbox id.

> **Attribution tradeoff.** Delegated calls wear the connected account's identity in
> Microsoft's activity logs (not a distinct app identity) — the same property Gmail
> has. The path to clean self-attribution is **agent-owned accounts** (the connected
> account is the agent's own licensed M365 user): a provisioning choice over this
> same flow, not a different guard. A separate app-only mode (the agent as its own
> *application* identity) is deferred and cannot cover Excel — Graph's workbook API
> is delegated-only.

## Platform setup (one-time, per platform — NOT per tenant)

The platform registers ONE multi-tenant Entra app (Ansur's), the mirror of the
platform Google app gmail uses:

1. **Register a multi-tenant Entra app** (supported account types: "Accounts in any
   organizational directory"). Create a **client secret**. Record the application
   (client) id and the secret.
2. **Register the redirect URI** `{PLATFORM_BASE_URL}/oauth/callback` (Web platform)
   on the app.
3. **Add the delegated Graph permissions** the connector requests at sign-in:
   `Mail.ReadWrite`, `Mail.Send`, `Files.ReadWrite`, `Calendars.ReadWrite`,
   `User.Read`, plus `offline_access` (for the refresh token).
4. **Wire the credentials into the platform:**
   - daemon (drives the OAuth flow): `MICROSOFT_CLIENT_ID` / `MICROSOFT_CLIENT_SECRET`
     — Helm `daemon.microsoftOauth.secretName` (a Secret with `client-id` /
     `client-secret`).
   - guards (refresh the per-tenant token): `MICROSOFT_CLIENT_ID` in the guard
     ConfigMap via Helm `guards.config.microsoftClientId`, and
     `MICROSOFT_CLIENT_SECRET` in the operator-created `ansur-guard-secrets`:
     ```
     kubectl -n ansur-guards-<env> create secret generic ansur-guard-secrets \
       --from-literal=GOOGLE_CLIENT_SECRET=... --from-literal=MICROSOFT_CLIENT_SECRET=... \
       --from-literal=DATABASE_URL=...
     ```
   - On the GitOps/ESO boxes, add the Doppler keys `MICROSOFT_CLIENT_ID` /
     `MICROSOFT_CLIENT_SECRET` (daemon) and `GUARD_MICROSOFT_CLIENT_ID` /
     `GUARD_MICROSOFT_CLIENT_SECRET` (guards), and add the matching ExternalSecret
     rows alongside the existing `GOOGLE_*` ones.

Without the daemon env the `m365` connector's OAuth flow is disabled (the daemon logs
a warning and `connector add m365` returns no authorize URL); without the guard env
the `graph` guard crashloops at boot rather than 403ing.

## Tenant-side: admin consent (the one step with a Gmail analogue)

The delegated scopes are requested at sign-in. A real Entra tenant often **disables
user consent**, so the heavier scopes (`Mail.ReadWrite`, `Files.ReadWrite`,
`Calendars.ReadWrite`) route to a **one-time admin consent** — the same step gmail's
heavier scopes face. An admin grants it once for the tenant; after that, users sign
in without re-consenting. Surface this in onboarding.

For Excel, the connected account must additionally have **edit access** to the target
workbook(s) in OneDrive for Business / SharePoint (OneDrive **Consumer** is
unsupported by the Excel API).

## Connect it (CLI-native, browser sign-in)

```bash
ansur connector add m365
#   → returns an /oauth/authorize URL. Open it; the connected account signs in and
#     consents (an admin consents once if the tenant disables user consent).
```

The callback stores the token bundle under `connector/m365/default`, flips the
connector to `connected`, and fires the wire reconcile — the `graph` guard comes up.
The connect check refuses `connected` unless `connector/m365/default` resolves, so a
guard never boots green without the credential it needs.

## How the employee calls Graph at runtime (for the bundle author)

The agent calls `graph.microsoft.com` **directly** (transparent HTTPS — no injected
URL env, no login step), addressing `/v1.0/me/…`:

- send: `POST /v1.0/me/sendMail` with the structured Graph message JSON.
- read: `GET /v1.0/me/messages?$select=…&$search=…&$top=…`.
- reply/forward/draft/move/flag, Excel workbook range/table reads + writes, and
  calendar events — see the bundle's `m365` skill for the exact calls.

The guard decodes the body per surface: mail → the same `{ to, cc, bcc, subject,
body }` intent the Gmail policy reads (recipient rules written once); Excel → row/cell
counts + sheet/table scope; calendar → attendees/subject. Reads forward by default;
writes route through the approval ladder (`mode: gated`) unless a rule rejects first.

## Gotchas

- **Address `/me`, never `/users/<id>`** — the token is delegated; `/me` is the
  connected account. The skill tells the agent this.
- **Reply/forward recipients are on the original message.** The guard preflights a
  GET of the original so recipient rules apply to a `reply { comment }` whose
  recipients aren't in the request body.
- **Attachment upload sessions bypass the guard** — `createUploadSession` returns an
  `uploadUrl` on a different host (SharePoint / Azure blob); the chunked PUTs of the
  bytes are unguarded. The example policy blocks session creation; if you allow it,
  record in the rules.yaml comment that the bytes are unguarded.
- **`AADSTS70011` / `invalid_scope`** at sign-in means a requested scope isn't added
  to the Entra app — add it and re-consent.
- **`AADSTS65001` / consent required** means the tenant needs admin consent — a
  tenant-side admin grant, not an Ansur bug.
- **Excel `ErrorAccessDenied`** usually means the connected account lacks edit access
  to that workbook, or it lives on OneDrive Consumer (unsupported).
- **`connected` in `connector list` ≠ provisioned.** Confirm the `*-graph-authz` pod
  is `Running` after a connect.
